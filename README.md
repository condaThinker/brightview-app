# 悦为因实修 · Brightview

[![Build APK](https://github.com/condaThinker/brightview-app/actions/workflows/build-apk.yml/badge.svg)](https://github.com/condaThinker/brightview-app/actions/workflows/build-apk.yml)

一个**离线优先**的每日实修打卡与记录 App。做三件事：早上到户外、晚上问自己五句话、每天看一课。

不是又一个习惯打卡工具。它刻意不做连续签到、不做排行榜、不做断签归零——因为**中断也是数据**。

> 同名知识库整理自「悦为因」公开分享的 153 集内容。本项目是非官方的个人实践工具，代码开源，内容版权归原作者。

---

## 下载安装

到 [Releases](../../releases) 下载最新的 `brightview-*-debug.apk`，传到手机上点击安装（需要允许"安装未知来源应用"）。

要求：Android 6.0（API 23）及以上。

> APK 由 GitHub Actions 自动构建（`.github/workflows/build-apk.yml`）：推送到 `master` 或打 `v*` tag 会编译，打了 tag 的那个会把 APK 自动附到 Release。也可以到 Actions 页手动点 `Run workflow`。
>
> 构建产物是 **debug 签名**，仅供自用与测试，不能直接上架应用商店。

## 它到底解决什么

大多数打卡 App 的隐含假设是"你不够自律，所以要被监督"。这套体系的前提正相反：**你不是懒，是污水系统一直在往你身上灌**。所以它不催你、不评分、不比较，只做两件事——把该做的事摆在你面前，把做过的事如实记下来。

具体落在三个动作上：

| 时段 | 动作 | 判定标准 |
|---|---|---|
| 晨间 | 早起打卡 | **人已经到户外**，拍一张带时间水印的照片（不是"起床按钮"） |
| 日间 | 盒子午休 | 20 分钟上限，到点必须出来 |
| 夜间 | 睡前五问 | 四句自问 + 一句收尾，不是打分表 |

## 睡前五问

首页直接列出五句，点哪一句就写哪一句；已经写过的点一下就能改单句，不动其它。

1. **善因** — 今天，为自己注入什么善因了？
2. **照见** — 今天，有没有得到一次「照镜子」的机会？
3. **善意** — 今天，有没有在外界感受到一丝一毫的善意？
4. **污水** — 此刻，还有没有残留一丝一毫的污水？
5. **收尾** — 今天无论好坏，都过去了。辛苦啦。（这一句不用回答）

17:00 之后首页主卡恒为睡前五问——夜里不该出现一张催你出门的卡。

## 主要功能

**晨间**
- 早起打卡：调用相机拍照，客户端 canvas 叠加时间水印，按打卡时刻与目标时间判定，过点只记「过点」不判失败
- 五呼吸：全屏呼吸圆 + 每拍一次震动，按原文顺序递进

**日间**
- 盒子午休：20 分钟倒计时，到点震动并强制提示

**夜间**
- 睡前五问（逐句可点、可单句编辑）
- 睡眠四问分诊：不想睡 / 不困 / 睡不着 / 睡不好，四种方向完全不同
- 躺下计划 vs 次日实际（熬夜侦探）
- 收尾仪式

**记录**
- 100 格大纸（10×10）、10 天分段
- 累计天数而非连续天数
- 断签补记：一句话写进全部空缺日，只算「记下了」不算「做到」
- 补卡机制：每满 10 天得 1 张、最多存 3 张、只能补最近 3 天、必须写一句为什么没做到；**补上的格子是空心虚线，不计入「已做到」**

**熏习（145 集课表）**
- 按原片真实发布日期间隔推进，一天只推一集
- 顺序锁：前面的没看完，后面的不打开
- 不强制：可以「才看到一半」，明天还是这一集，并显示挂了几天

**修行**
- 七剑：每一剑可逐步骤勾选，进度跨天保留
- 调心六法、金三角体检、四重境自评
- 红尘炼心：起床、穿衣两组动作逐项打勾

**人生截图**
- 7 屏手写流程（三魔自评 → 难题 → 心得 → 技能点）
- 第一张锁死不可改，后续可追加，追加自动带日期
- 时间树：看每一张之间多了什么
- 第 100 天提示截第二张，两张并排对照

## 设计上刻意做反的地方

| 常见做法 | 这里的做法 | 为什么 |
|---|---|---|
| 连续签到、断签归零 | 累计天数，断的那天只是浅色 | 断签归零把中断定义成失败，紧接着就是破窗 |
| 排行榜、好友对比 | 完全没有 | 只跟自己比 |
| 21 天养成 | 百日 / 七年 | 21 天速成是把长期问题短期化 |
| 补卡即算达标 | 补卡只补记录，不算达标 | 一旦补的格子算成绩，就成了自欺工具 |
| 弹窗催打卡 | 只在对应时段把卡摆出来 | 不由 App 判断你该不该 |

## 数据与隐私

- **全部数据只存在这台设备上**：`localStorage` + IndexedDB，不上传、不联网同步
- 照片存在本地 IndexedDB，不经过任何服务器
- 只有主动点「去 B 站看这一集」才会跳转外部链接
- 设置页可导出 JSON 备份与 Markdown 日记，随时带走

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 壳 | Capacitor 6 | 复用已验证的 Web 实现，拿到原生相机、持久存储与安装包 |
| UI | 原生 HTML/CSS/JS（单文件） | 无框架、无构建步骤，`www/index.html` 就是全部前端 |
| 存储 | localStorage + IndexedDB | 离线优先，无后端 |
| 构建 | Gradle + GitHub Actions | 推送 tag 自动出 APK |

选择封装而不是重写的原因：这套逻辑（145 集课表、时间树、补卡规则、五问流程）已经在真机上验证过行为，封装能一比一保留；重写只会引入新 bug，且对"每天打卡"这类低频重交互场景收益有限。

## 本地构建

```bash
# 需要 JDK 17 + Android SDK（compileSdk 34）
npm install
npx cap sync android
cd android
./gradlew assembleDebug
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

正式签名：在 `android/keystore.properties` 填入 keystore 路径与口令（该文件已被 `.gitignore` 忽略），`build.gradle` 会自动启用 release 签名。

## 目录结构

```
www/index.html        # 全部前端逻辑（单文件）
android/              # Capacitor 生成的 Android 工程
.github/workflows/    # 自动构建 APK
capacitor.config.json # appId / appName / webDir
```
